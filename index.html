What a machine remembers

Double-click the exe and a window opens. Give it any argument and it stays a console tool. Both faces drive the same engine and the same 78 collectors, and everything below ships in the one file.

Everything ever attached

USB sticks and drives, Bluetooth pairings, monitors with their serials, printers: read from what Windows kept, including devices unplugged long ago, with first-install and last-removal times.

Where it went, what ran

Saved Wi-Fi networks and their connect history, programs run with when and how often, files opened, saved, searched and deleted, sign-ins, camera and microphone use, and the volatile state that vanishes at reboot.

The access ledger

Absence of evidence is never reported as evidence of absence. Every run ends by naming what was read, what was refused, and what elevation would add, so the report cannot lie by omission.

Is something weird here?

Rules that work on first contact, and a baseline that adds a “new since” layer. The answer never says “clean”: it says what ran, what matched, and what could not be read, with the evidence rows behind every finding.

Stick-first, deadbox-ready

Run it from a USB stick and reports land on the stick, not the host. Point -root at a mounted dead volume to read another machine’s history, or bag the raw evidence files with a hashed manifest.

Reads, never manufactures

No network code, banned by a structural test. It never spawns a process, because doing so writes the very evidence it came to read. Secrets are reachable and left alone: it reports a credential exists, never what it is.

The command line

Examples use lfr for brevity: rename the exe freely, nothing depends on the name. No verb takes a path; it examines the machine it runs on, or the dead volume you point -root at.

quick taste
$ lfr                          # every area at once
$ lfr devices                  # everything ever attached
$ lfr all -find kingston       # all it remembers about that stick
$ lfr runs -since 7d           # what executed this week
$ lfr all -f html -out report.html  # one self-contained report
$ lfr collect -raw -out .      # the raw evidence bag, hashed
$ lfr all -root F:\            # deadbox: a mounted dead volume

Questions, answered

Windows SmartScreen warns about the download. Why?
The binary is not code signed: certificates cost money every year and would not change what is in the file. Verify the SHA-256 hash against the one published above, then choose More info, Run anyway. The build is reproducible from source, so the published hash is checkable end to end, and copies run from a USB stick or an internal share never see the prompt.
Do I need administrator rights?
No. It runs as a standard user and reports honestly: the access ledger ends every run naming what was denied and what elevation would add. Measured on Windows 11, that is things like Wi-Fi first-joined dates, gateway MAC history and per-user run times. Elevation is never requested; run it elevated when you want those collectors too.
Does it send anything anywhere?
No. There is no network code in the binary at all: the source enforces a module-wide ban on Go's net and os/exec packages with a structural test. It also never spawns a process, because starting one on a machine under examination writes the very prefetch, shimcache and BAM entries it came to read.
What does it write to the machine it examines?
Nothing, during collection: reports and the raw evidence bag land beside the exe, on your stick, and locked hives are copied to the stick to be parsed. The one named exception is prepare, which turns on Windows' default-off auditing so a later run has more to read. It is fenced: a warning first, an explicit -y, admin required, every change capped, and prepare -undo restores every value from a journal saved before the first write.
Can it read a disk from another machine?
Yes. Mount the dead volume and pass -root: registry- and file-borne history is read straight from the dead hives and files. Collectors that need the live machine are named in the ledger rather than silently skipped, and the report states which volume the evidence came from, so a deadbox run is never mistaken for a live one.
Does it read passwords or Wi-Fi keys?
No, deliberately. Wi-Fi keys, browser logins and vault contents are reachable and are left alone: it reports that a credential exists, its target and its dates, never the secret itself. That boundary keeps the binary safe to hand to anyone.
